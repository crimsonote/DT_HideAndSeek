# 测试清单（部署后逐条验）

> 每条都对应**一个真实踩过的坑**，所以"通过标准"写的是**你会看到什么**，不是"代码应该怎样"。
> 反例：这条清单里没有一条是"读代码确认"——全都是**能在游戏里看到的**。

---

## 0. 启动前的三项检查（漏了这三项，后面全白测）

| # | 做法 | 通过标准 | 为什么 |
|---|---|---|---|
| 0.1 | 看日志加载行 | `[HS] HideAndSeek 1.1.0 加载完成（DT_Tools 已检测到）：启用 N，跳过 M，**失败 0**` | **失败必须为 0**。补丁挂不上**不报错**，只静默失效 |
| 0.2 | 执行 `hs_check` | 想测的功能都 `loaded`；触发后 `hits > 0` | 唯一能**区分"没挂上"和"挂上但没触发"**的手段 |
| 0.3 | 看日志的「已跳过功能」 | 要测的段**不在**名单里 | **段开关会连带跳过整类所有补丁**（坑：命令能生成对象，却没有任何钩子处理它） |

**坑记录**：`[Dummy] Enabled=false` 时，`hs_dummy add` 能造出假人，但选角钩子从未挂载 ⇒ "假人不会自动随机"查了很久。
**教训**：`defaultEnabled` 改了，`.cfg` 也要同步改 —— BepInEx 只在**键不存在**时用代码默认值。

## 1. 假人（Dummy）

| # | 操作 | 通过标准 |
|---|---|---|
| 1.1 | `hs_dummy add 3` 后进对局 | 3 个假人各有**不同**角色，且**不用等 40 秒**（选角阶段就会定） |
| 1.2 | 玩**两局**（第一局放几个假人） | 第二局开局，假人**席位是空的**；`hs_dummy add` 不报「人数已达上限」 |
| 1.3 | 连开两局不做任何操作 | 第二局 `hs_dummy list` 里**没有**上一局残留 |

**坑记录**：① `-2`（随机）曾被我们自己解析成具体角色 ⇒ 丢掉了"系统随机"的语义；② 跨局席位靠 `IsDummy` 判断，而原版在 `StartLobby` 已把它抹掉 ⇒ 永远清不掉。

## 2. 美幸（Miyuki 全图标记）

| # | 操作 | 通过标准 |
|---|---|---|
| 2.1 | 当美幸，让其他人在附近走动 | 标记**连续跟随**，不是一跳一跳 |
| 2.2 | 把 `[MiyukiScan] ResendIntervalMs` 热改成 50 | 立刻更顺（说明节流在生效） |
| 2.3 | `ShowSelfOnRadar=true` | 地图上多出**自己**的点（测试开关） |

**坑记录**：节流时钟用了 `SurviveTime` —— 它是 **int、每秒 +1**，所以 `now-last < 0.2f` 在同一秒内恒真 ⇒ **200ms 节流退化成"每整秒一次"**，看着就是 1 Hz 跳点。已改用 `Time.realtimeSinceStartup`。
**教训**：**任何小于 1 秒的时间判定都不能用 `SurviveTime`**。

## 3. 莲（预警 + 追踪 + 蜡烛动画）

| # | 操作 | 通过标准 |
|---|---|---|
| 3.1 | 有人死亡（莲在场） | **全房活人**看到指向尸体的箭头 + 一声警告音 |
| 3.2 | 3.1 之后等 25 秒 | **箭头消失** |
| 3.3 | 有人连续死两次（间隔 < 20 秒） | 箭头跟随最新尸体，不叠加、不永久残留 |

**坑记录**：`S_NOTIFY_ARROW` / `S_PIN_MOVE` **都没有"时长"字段** —— 发出去就一直在。
要它消失**必须主动发删除包**（`S_REMOVE_ARROW`，且 `Pos` 必须与最后一发**精确同值**）。
**教训**：凡是"客户端画一个东西"的包，都要问自己"**它怎么消失**"。

## 4. 路易斯（念力，已开启）

| # | 操作 | 通过标准 |
|---|---|---|
| 4.1 | 用念力标记一个人，再让别人杀死他 | 杀手被**时停 3 秒**，随后进入"力竭"（体力空，约 5 秒） |
| 4.2 | 用念力标记一个人，**自己**去杀他 | **自己不受**时停/力竭影响 |
| 4.3 | 标记一个人后观察 | 每 15 秒出现一次指向他的**世界箭头**，持续 3 秒，**跟着他移动** |
| 4.4 | 让被标记的人死掉 | 箭头**立刻消失**，且不再刷新 |
| 4.5 | 看平板地图 | **不应该**因为追踪而多出标记（我们走的是世界箭头通道） |

**坑记录**：① 一度用了 `92000+pid` 当 pin 类型 —— 而**世界箭头要求 ID 是真实 PlayerId**，所以那样根本没箭头、只在地图上多一个点；② `S_PIN_MOVE` 在客户端**无条件刷"场景地图"和"平板"两处**，没有按 ID 分岔 ⇒ 用它在平板上必然留痕；③ 追踪若不挂"目标移动"，箭头只是三段断续的静态位置。

## 5. 门锁（两段上锁 + 进度条）

| # | 操作 | 通过标准 |
|---|---|---|
| 5.1 | 持鱼对门**3 秒内连敲 3 下** | 日志出现「上锁进度已激活 0/N」 |
| 5.2 | 再敲 E | 进度推进；门头出现**紫红进度条**（就是原版"黑方拆门"那条的位置） |
| 5.3 | 敲满 | 门锁上 |
| 5.4 | 把 `[KeyLock] BlinkGauge` 热改成 true | 充能期间进度条**每秒在进度与 0 之间闪** |
| 5.5 | 拿鱼按 E 后立刻让**别人**去开同一扇门 | 别人开不开（约 1 秒内被拦） |
| 5.6 | 上锁过程中一直按住 E 不松 | 保护被不断刷新，门最终锁上 |

**坑记录**：① 原先"胶未干"保护只写在 `state==2` 分支里，而那几秒门还是普通关闭态 ⇒ 别人一开就打断；② 进度条配色是客户端**代码常量**（紫红），房主端改不了。

## 6. 跨局残留（通用，每加一个"记时间"的功能都要过一遍）

| # | 操作 | 通过标准 |
|---|---|---|
| 6.1 | 第一局用掉某个有时限的功能（鱼/汽水/CD/仪式…） | 第一局行为正常 |
| 6.2 | **立刻开第二局**，不再触发那个功能 | 第二局开局该功能**可用**（不是"已售罄"/"CD 中"） |

**坑记录**：`TimeManager.SurviveTime` 每局被 `ResetSurvival()` 设回 **420**（不是 0）。
上一局记的"250 秒"在新局算出来是负数 ⇒ `now - t > window` 永不成立 ⇒ **记录永不过期**。
**教训**：任何 `Dictionary<pid, float>` 形式的时间表，都要在 `StartSurvive` / `StartLobby` 清。

## 7. 配置相关

| # | 操作 | 通过标准 |
|---|---|---|
| 7.1 | 改了某个功能代码里的默认值后**重装** | `.cfg` 里那行**也要一起改**，否则老用户拿不到新值 |
| 7.2 | 在 DT CONSOLE 的配置页改一个值 | **立刻生效**（改的是内存）；改 `.cfg` 文件则要**重启** |
| 7.3 | 改配置后看是否落盘 | 上游 DT_Tools 的 `SaveOnConfigSet=false` ⇒ **必须显式 Save**，否则退出即丢 |

**坑记录**：`[KeyLock] LanternItemId` 是首次启动时按当时默认值写进 `.cfg` 的；后来代码把默认从 `4006` 改成 `1059` 也**进不去** ⇒ 症状是"发的提灯图标缺失（白方块）+ 永远黏不了门"。

## 8. 编译期就该拦住的（不看游戏也要过）

| # | 检查 | 通过标准 |
|---|---|---|
| 8.1 | 构建输出 | **0 error / 0 warning**（`CS0184` 这类"表达式恒为某类型"的警告**必须当错误看**） |
| 8.2 | 中文是否正常 | 在 DLL 里按 **UTF-16LE** 搜中文（不是 UTF-8）；乱码说明文件丢了 BOM |
| 8.3 | 新 `.cs` 文件 | **必须带 UTF-8 BOM**（否则中文在编译期就被 GBK 解坏，且**不报错**） |

**坑记录**：`CS0184: 给定表达式始终不是所提供的("DeadlyTrickStage")类型` —— 我一度忽略它，结果
`d is DeadlyTrickStage` **永远为 false** ⇒ `InDtRange` 恒假 ⇒ 莲的假光照与整套仪式**全部失效**。
**根因**：`DeadlyTrickStage` / `Cabinet` / `Occult` / `DeviceManager` / `Corpse` / `Player` 都有**客户端与服务端两个同名类**，
C# 会把裸名字解析到**外层（全局）命名空间**那个。→ 必须用 `using GameXxx = Server.Game.Xxx;` 显式限定。
