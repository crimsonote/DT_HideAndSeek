# 回放·磁带生命周期（排查与改动依据）

> 这份文档是**改动 `Features/Rule/EndReplay*.cs` 之前的对照表**。
> 回放这条链路上出过的问题，几乎都是"改了 A 处的假设，B 处跟着坏"——
> 所以每次动手前，请先对照第 2、3 节（两个基准 / 三个角色）与第 6 节（症状→原因）。
>
> 行号引用格式 `:12345` 指向 `.tmps/decomp/Assembly-CSharp.decompiled.cs`（原版反编译）。
> 本仓库自己的代码用文件:行。

---

## 1. 一句话总览

```
对局结束 → 拦截 ChangeGameState(TotalResult)
   ├─ 登记 Clip（窗口 before/after + 事件时刻 At + 被拍摄者）
   ├─ 向"录制者"索取磁带（S_RECORD_REPLAY 只是预约；真正索取是 S_REQUEST_TAPE）
   ├─ 收到 C_TAPE → 原版自动 Broadcast(S_TAPE)？不：我们先 TrimTape 再自己广播
   ├─ 没收到 → EndReplayHostTape 合成一段（"服务端兜底"）
   └─ 播放：客户端 BeginTape → 逐帧 Update → 下一段 … → 放完继续结算
```

**两种素材来源**（务必分清，它们的"能力"不同）：

| | 客户端磁带 | 服务端兜底合成 |
|---|---|---|
| 谁产生 | 真人客户端回传的录制缓冲 | `EndReplayHostTape` 用 5Hz 采样现造 |
| 设备帧（传送门等） | **有**（客户端会录 `AddShot`） | **没有**（我们只产安全帧，见 §5） |
| 帧密度 | 客户端录制密度（实测约 10 帧/秒） | 采样 5Hz + 插值 |
| 首帧 | 磁带自带（录制者本人）→ 被我们换成观察者/替身 | 我们直接造 |
| 何时用 | 默认首选 | 该段没等到磁带时 |

## 2. 时间基准：一条磁带里混着**两种**（最容易踩）

原版客户端录制时（`RecordManager.Recording` `:296-297`）：

```csharp
shot.TimeStamp = isStartShot ? (float)Managers.Game.SurvivalTime : Managers.Game.ClientTime;
```

| 字段 | 类型 | 含义 | 谁在用 |
|---|---|---|---|
| `Managers.Game.SurvivalTime` | `int`，**服务端下发**（`S_TIME`，`:42286-42288`） | 本局存活时间（秒），开局归零 | **每秒一次的全员出场帧**（`isStartShot = true`） |
| `Managers.Game.ClientTime` | `float`，客户端本地 | 客户端自己的时间线 | 其余**全部**帧（移动/编辑/特效/区域） |

**实测数据**（同一局）：出场帧 ≈ `463~502`，其余帧 ≈ `65~114` ⇒ 差 ≈ **388** 且**在本局内恒定**
（偏移由"客户端何时加入这一局"决定，跨局会变）。

### 影响与对策

- 我们的窗口 `[anchor − before, anchor + after]` 是按**锚点**推的，而锚点来自 `NormalTimeEdit`
  ⇒ 它是 `ClientTime` 基准 ⇒ **窗口只匹配"其余帧"**，出手帧天然落在窗口外。
- ⇒ 所以裁剪后**必须自己补一轮"全员出场帧"**（`EndReplayFeature` 的 `RosterFrames` / 阶段 1）。
  这不是可选优化，**是正确性要求**：没有出场帧的人不会被 `ApplySpawn` 生成到场景里。
- ⇒ 裁剪输出前**必须按 `TimeStamp` 排序**（保留首帧）。客户端播放是
  `while (…) { if (shot.TimeStamp > _currentTime) break; … }`（`RecordManager.Update` `:31976-32056`），
  输出里一旦出现"大值夹在小值中间"，它在那一帧就 `break`，**后面所有帧都不执行**。

> ⚠ 想统一基准（把出场帧重映射到 `ClientTime`）是可行的（偏移恒定），但**没人做过**，
> 且当前"排除 + 自补"的路子已经够用 —— 改它要重跑全部回归。

## 3. 三个角色：**录制者 / 被拍摄者 / 剪影槽位**

这三个概念在本仓库里长期混用（字段名 `Clip.RecorderId` 其实常常是"被拍摄者"），是最大的错误来源。

| 角色 | 是什么 | 由谁决定 | 约束 |
|---|---|---|---|
| **录制者** | 谁**录**了这卷磁带（收到 `S_RECORD_REPLAY`、能回 `C_TAPE`） | 只有**真人**才可能是 | 假人**没有**录制者 |
| **被拍摄者** | 我们想让**镜头拍**的那个人（本段主角） | `Clip.RecorderId`（字段名误导） | 真人段里他就是录制者；假人段里只有他 |
| **剪影槽位** | 客户端把"黑剪影"打在谁身上 | **磁带首帧的 id**（`BeginTape` 折出 `_blackId`，末尾 `Players[_blackId].ChangeSilhouette(true)`） | **不能是被拍摄者本人**（否则他被涂黑）；**不能用 id 0**（本机特殊值，各机冲突） |

### 客户端的判定链（读码依据）

```
BeginTape（:31902-31936）
   PrepareDevices(tape[0].TimeStamp)          // 只隐藏 IsTemporary && SpawnedAt > eventTime 的设备
   ForceSpawnReplayTemp(MyPlayer.Name)        // 造 id=0 的本机替身
   foreach (Players) Despawn(id)              // 全体 SetActive(false)（_cache 保留）
   _blackId = (tape[0].Spawn.PlayerId != _myPlayerId) ? tape[0].Spawn.PlayerId : 0
   ChangeMyPlayer(_blackId)
   ApplySpawn(tape[0].Spawn)                  // 首帧必须是 SpawnShot（硬要求）
   Players[_blackId].ChangeSilhouette(true)   // ★ 剪影打在这里
   _playIndex = 1; _currentTime = tape[1].TimeStamp
```

```
ChangeArea(AreaSnapShot)（:29605-29611）
   ChangeRoom(RoomDic[area.RoomId])           // RoomId 必须合法，0 会抛
   Managers.Game.CameraTarget = GetDevice(area.CameraTargetId)   // ★ 镜头跟谁
   Managers.Game.Darkness = !area.IsLight
```

⇒ **剪影槽位（首帧 id）与相机目标（`AreaShot.CameraTargetId`）是两个独立字段**，
  原版没有"把相机送到别的房间"的实现，相机被约束在当前房间边界内 —— 自造跨房间机位必然"漂出去又被拽回"。

### 可用作剪影槽位的人（按优先级）

1. **已死 + 仍在房间 + 本段磁带里有出场帧**（最干净：`IsGhost=true` ⇒ 回放期 invisible）
2. **已死 + 本段磁带里没有出场帧**
3. **存活，但本段"没有在场景中排到"**（= 磁带里**没有他的出场帧** ⇒ 不会被 `ApplySpawn` 生成）
4. 都没有 ⇒ **当事人自己**（接受被涂黑；日志会 Warning）

> ⚠ **判据必须用"有没有出场帧"，不能用"窗口内有没有帧"**：
> 客户端磁带是**数据广播**、录了**全房所有人**的位置帧，所以"窗口内有帧"≈所有人。
> 用错判据的实测症状：`拿刀`这种"局刚开始、还没人死"的幕永远挑不到替身 ⇒ 退回当事人 ⇒ **拿刀那幕黑漆漆**。

## 4. 一段磁带的处理链

| 步骤 | 代码 | 输入 → 输出 | 易错点 |
|---|---|---|---|
| **① 登记** | `CollarBombHook` / `KillHook` / `WhiteWinNoteHook` … | 事件 → `Clip{At, Before, After, RecorderId, Key}` | `At` 的基准：自爆幕必须用**自爆走完**（`OnDeadCollarBomb` 是"开始"，`PushAfter(6000)` 才是死亡） |
| **② 预约** | `RequestRecord` → `S_RECORD_REPLAY{RecordTime=key}` | 让客户端把"此刻"记成一个可裁事件 | 假人**收不到**（没客户端）⇒ 只 `AddClip` |
| **③ 索取** | `RequestTapes` → `S_REQUEST_TAPE` | **每个 key 单独一包** | ⚠ **一次塞多个 key 会让客户端自己裁**（`trim = list.Count >= 2`），而它的裁剪窗口是**硬编码 3 秒前/5 秒后**（`:189-190`）且按 `ClientTime` 量纲 ⇒ 我们的 key 量纲不符时**裁出空带** ⇒ 静默降级服务端 |
| **④ 裁剪** | `TrimTape` | 原始带 → 窗口内的帧 | ① 找锚点（最后一枚 `NormalTimeEdit`；没有则用磁带末尾）② 补全员出场帧 ③ 丢自爆尸体 `AddShot` ④ **排序（保留首帧）** |
| **⑤ 广播** | `BroadcastReplay` / `S_TAPE` | 发给全体（含换剪影的变体） | 幽灵替身撞上某观众自己的 id 时，要**单独给他换一个替身再发一份** |
| **⑥ 兜底** | `TrySendHostTape` → `EndReplayHostTape.Build` | 没等到磁带时现造 | 只产**安全帧**（见 §5）；首帧=替身（`IsGhost=true`），相机目标=被拍摄者 |
| **⑦ 播放** | 客户端 `BeginTape` / `Update` | 帧 → 画面 | 时间戳必须**非递减**；首帧必须 `SpawnShot` |

## 5. 客户端会崩/会卡死的路径（避雷清单）

| 帧 / 效果 | 结论 | 原因 |
|---|---|---|
| `AddShot`（**尸体**） | **禁用** | `RecordManager.ApplyAdd` 对 `Corpse` 无条件调 `SetInfo`；`Corpse.SetInfo` 的 bomb 分支第一句 `GetComponentInChildren<SkeletonAnimation>().gameObject.SetActive(false)` 第二次调用取到 null ⇒ NRE；而 `_playIndex++` 在 switch **之后** ⇒ 同一帧每帧重试 ⇒ **整段回放卡死** |
| `AddShot`（**设备**） | **安全**（未启用） | `ApplyAdd` 只对 `Corpse` 调 `SetInfo` ⇒ 设备不会走那条路。**这是"补设备帧"（传送门等）的可行路径** |
| `EffectShot{FlashVfx/ScopeVfx/ArmbandVfx}` | **禁用** | 客户端无条件解引用 `GetPlayerCache(deviceId)` 的 `CharData`/`transform`，而观众自己的 id 会被改写成 0（0 号替身是半成品）⇒ 空引用 ⇒ 卡死 |
| `EffectShot{DyingVfx}` | 可用 | `PlayDying()`：`NecklaceWork` 音效 + **前 1.0 秒哑期**（`intensity=0`）+ 4 轮递进闪烁 = **5.875 秒**，≈ `PushAfter(6000)`。**只需触发一次**（纯客户端 DOTween，段切换不打断）|
| `EffectShot{BlackOutVfx}` | 可用但**会跨幕** | 客户端是「开 → `DoActionAfter(2f)` → 关」，**服务端没有"立刻取消"的接口** ⇒ 会持续满 2 秒 |
| `EffectShot{MineBombVfx}` | 可用但**会残留** | UI 弹层（`UI_DespairBombEffect`），回放结束收不干净 ⇒ 残留到大厅。现由命令 `hs_panel` 单独触发 |
| `DespawnShot` | 可用 | 让玩家对象 `SetActive(false)`；**不要**放在闪烁期间（会掐掉动画） |

## 6. 症状 → 可能原因 → 怎么验证

| 症状 | 最可能的原因 | 验证 |
|---|---|---|
| **拿刀幕黑漆漆**（人或整幕黑） | 剪影槽位落到了被拍摄者身上（挑替身失败） | 日志 `片段【拿刀】… 主视角=`：出现 `原版 #N` 就是没换成功；`隐藏观察者#N(Ghost)` 才对 |
| **看不到用传送门、像穿墙** | ① 该幕降级成服务端合成（**没有设备帧**）② 客户端带里设备帧也没被 spawn | 日志 `重裁 …` vs `客户端磁带没到 ⇒ 服务端兜底合成`；前者才可能有设备帧 |
| **走路一跳一跳 / 瞬移** | ① 输出帧**乱序** ⇒ 客户端 `break` ② 帧密度本身低（客户端约 10 帧/秒） | 日志 `留 N 帧（… 排序前逆序 K 处）`：K>0 说明排序在救场；再看得出的帧数与窗口秒数之比 |
| **项圈闪烁看不到** | 触发帧落在"被切走的那一段"，或可用的播放时长不足 1.0 秒哑期 | 日志 `触发闪烁 N 枚`；自爆幕第一段必须独占 ≥1.5 秒 |
| **自爆瞬间没有"爆"** | 只有 `DespawnShot`（人消失）；压暗/面板都不是"爆炸画面" | 原版真正的爆炸动画在**尸体**对象里（禁用），只能靠压暗/面板近似 |
| **画面里多一个幽灵** | 剪影槽位所在的人被 `spawn` 出来了 | 日志 `出场名单`；看那个 id 是否 `(幽灵)` 且在替身位置 |
| **白胜却弹黑方提示** | 原版 `Player.set_Color`（`:175364-175379`）在"有人变 `Black` 且 `MasterMind != null`"时发 `S_NOTIFY_BLACK` | 日志搜 `NoMasterMind：已跳过黑幕分配`（应出现）；`MasterMind` 是跨局字段，必须显式清 |

## 7. 回归清单（每次改完照着走一遍）

**日志判据**（`BepInEx/LogOutput.log`，搜 `[HS] EndReplay`）

- [ ] `失败 0`（加载报告）—— 补丁必须全挂上
- [ ] 每段都有来源结论：`重裁 N → M 帧` **或** `客户端磁带没到 ⇒ 服务端兜底合成`
- [ ] 每段的 `主视角=` **不是** `原版 #N`（除非确实没有可用替身）
- [ ] `排序前逆序 K 处`：K 应为 0 或很小
- [ ] 自爆幕：第一段 `触发闪烁 N 枚`（N>0）且 `触发闪烁` 只出现在第一段
- [ ] 自爆幕末段：`本段移走 N 人`（N = 被处决人数）
- [ ] `NoMasterMind：已跳过黑幕分配` 每局至少出现一次

**画面判据**

- [ ] 拿刀幕：拿刀的人**本色**出场（不是黑块）
- [ ] 自爆幕：看到项圈**闪烁**（且越来越快）→ 人消失
- [ ] 白胜幕：每段都是"同一段时间"的不同视角，依次播
- [ ] 黑方收尾幕：断电视野、爆炸落在中间
- [ ] 回大厅后画面**恢复正常**（没有残留遮罩/压暗/面板）

## 8. 待验证 / 待决事项（不要当成已解决）

1. **"走路穿墙"**：本节 §6 的两个候选原因**都还没有实机确认**。需要一局日志看
   `排序前逆序 K 处` 与帧密度。
2. **设备帧（传送门）**：`AddShot{Device}` 读码上安全，但**我们从未发过**；
   要不要补"服务端采样设备"是**未定**的功能决策。
3. **时间基准统一**：偏移恒定 ⇒ 理论可统一，但未实施（当前用"排除 + 自补出场帧"）。
4. **`Clip.RecorderId` 改名**（→ `SubjectId`）：消除 §3 的命名混用，改动面较大，未做。
5. **幽灵替身每段开头闪现一帧**：`BeginTape` 里"首帧 `ApplySpawn`"发生在 `_isPlay = true` **之前**
   ⇒ 那一刻 `IsPlaying == false` ⇒ 走 `RefreshGhostVisual` **case 1**（画幽灵）。
   房主侧**无法**修（时序在客户端内部），需要客户端补丁。
6. **`MineBombVfx` 残留**：需要客户端侧清理（未做）。
