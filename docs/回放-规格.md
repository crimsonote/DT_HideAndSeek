## 1. 客户端硬约束（违反 = 崩 / 卡死 / 整段静默跳过）

| # | 约束 | 证据 | 违反的后果 |
|---|---|---|---|
| C1 | 每段磁带 `Count >= 2` **且首帧是 `SpawnShot`** | `BeginTape :31905` | 静默跳过整段（连转场都不播） |
| C2 | `TimeStamp` 必须**非递减** | `Update :32010`：`if (TimeStamp > _currentTime) break;` | 大值夹在中间 ⇒ 那一帧 break ⇒ **后面所有帧不执行** |
| C3 | `PlayerId == _blackId` 的 `SpawnShot` **被无条件跳过**（不看时间戳、不做 ApplySpawn） | `Update :31997-32009` | 首帧锚点不会被"自己的"出场帧重新摆位（这是必要的，但必须知道） |
| C4 | `PlayerId == _myPlayerId` 的 `SpawnShot` 会被**改写成 0** | `Update :31999-32002` | 每台机器看到自己的替身；"幽灵替身恰好是某观众本人"⇒ 他那一份坏掉 |
| C5 | `ChangeMyPlayer(_blackId)` 是 `_cache[id]` **直接索引** | `:31926`、`:31525` | id 不在缓存里 ⇒ `KeyNotFoundException` ⇒ 整段回放中断 |
| C6 | `ChangeArea` 走 `RoomDic[RoomId]` | `:29607` | `RoomId = 0` ⇒ `KeyNotFoundException` |
| C7 | **每段必须自带 `NormalTimeEdit`** | `ApplyEdit :32167-32188` + `DeltaTime :28706` | 继承上一段遗留的 `TimeScale = 0.25` ⇒ 8 秒的带子要走 32 秒 ⇒ 只有开头几帧被执行（"哑剧"） |
| C8 | **不能发 `AddShot(Corpse)`** | `ApplyAdd` → `Corpse.SetInfo`；二次调用时骨架已被自己关掉 ⇒ `GetComponentInChildren<SkeletonAnimation>()` = null | NRE；而 `_playIndex++` 在 `switch` **之后** ⇒ 同一枚帧每帧重试 ⇒ **整段卡死** |
| C9 | **不能发 `EffectShot{FlashVfx/ScopeVfx/ArmbandVfx}`** | `PlayEffect` 无条件解引用 `GetPlayerCache(deviceId)`，而"本机玩家"的 id 被改写成 0、0 号替身是半成品 | 同上，卡死 |
| C10 | 剪影只打给 `_blackId` | `:31928-31931` `ChangeSilhouette(true)` | **首帧的 id 谁，谁被涂黑** |

> C8/C9 是"同一枚帧每帧重试"这个结构的后果 —— 只要有一枚帧会抛，**整段回放就永久卡住**。
> 所以宁可少一幕，也不要发不确定安全的帧。

## 2. 时间基准（最容易出错的地方）

- **T1** `shot.TimeStamp = isStartShot ? SurvivalTime : ClientTime`（`:31836`）
- **T2** ★ 每轮 `RecordAllType` 的**第 1 帧**（录制者自己）用 `SurvivalTime`，
  **同一轮的其余全员帧**用 `ClientTime`（`:31800-31810`，只有第一枚传 `isStartShot: true`）
  ⇒ 磁带的时间戳序列是 `[S, C, C, …, S, C, C, …]` —— **每 1 秒一个大跳**
- **T3** 实测：`S ≈ 463~502`、`C ≈ 65~114`，差 ≈ **388**（本局恒定，跨局会变）
- **T4** 服务端 `Managers.Game.ClientTime` 与客户端同源（都由 `S_TIME` 驱动）⇒ 房主侧可以拿它当基准
- **T5** ★★ **窗口必须只有一个定义。**
  现有实现有两条路各算一次：服务端合成用 `clip.At ± Before/After`，客户端磁带用 `磁带锚点 ± Before/After`。
  而 `At = ClientTime + atOffset` **含偏移**、磁带锚点（`NormalTimeEdit` = 事件时刻）**不含**
  ⇒ 两者差一个 `atOffset`。自爆幕 `atOffset = CollarToDeadSec = 6`
  ⇒ 客户端磁带路的窗口落在 `[t0−6, …]`（自爆**之前**），这就是"看不到闪烁"的结构性原因。

## 3. 录制端事实（决定了"素材里能有什么"）

- **R1** 只在 `IsAlive && !IsSpectator && State == Survive` 时录（`:31819-31822`）⇒ 死亡/旁观期**完全不录**
- **R2** 磁带**一定以录制者自己的 `SpawnShot` 开头**（`:31823-31834` 的空表守卫要求第一枚必须是自己的）
- **R3** 环形缓冲 `MAX_RECORD_LENGTH = 14`（`:31551`）⇒ 稳态只保留**最近约 14 秒**
- **R4** `RecordingTape[key]` 要到 `T + 9s` 才落地（`:31668`）；在此之前索取会走"当前缓冲"分支
- **R5** 移动帧密度 = `C_MOVE` 发包密度：`UpdateMovePacket` 跑在 `FixedUpdate`、节流 `>= 0.1f || 方向变更`（`:14865-14894`）
  ⇒ 站桩 ~10 Hz；转向**立即补发**；鼠标跟随时可达 FixedUpdate 频率（≈50 Hz）
- **R6** ★ **覆盖面 = AOI 内**：`Player.Move` 只 `Session.Send`(自己) + `BroadcastToDeadPlayers` + `BroadcastToPlayerAndObservers`（`:175910-175912`）
  而死者**不录制** ⇒ 活人交上来的磁带**只有 AOI 内的画面**（不是"全房所有人"）
- **R7** **未录制**：音效、物品增删、线索、任务进度、审判投票、绘图、尸体元数据、PrivateInfo、冷却、击退、表情
  ⇒ `PublicPlayerInfo` 的 8 个字段就是磁带里玩家信息的上限
- **R8** 假人**没有客户端** ⇒ 永远交不上磁带（只能服务端合成）
- **R9** 录制会产生的帧类型：`SpawnShot / MoveShot / AddShot / RemoveShot / DespawnShot / RespawnShot / ModifyShot / StateShot / AreaShot / EffectShot / DeadlyTrickShot / EditShot`

## 4. 素材来源（三条路的能力不同，不能当成同一件事）

| | 客户端磁带 | 服务端合成 | 占位磁带 |
|---|---|---|---|
| 谁能提供 | 真人（活过那一局） | 房主自己 | 房主自己 |
| **设备帧**（门/传送门） | **有** | 无 | 无 |
| 覆盖面 | AOI 内 | **全员**（采样） | — |
| 帧密度 | 10~50 Hz | 现在 5 Hz（**应改挂 `Player.Move` 以求同频**） | 2 帧 |
| 首帧 | 录制者本人 ⇒ 必须换 | 我们直接造 | 我们直接造 |
| 光照 | 每帧真实（`AreaShot.IsLight`） | 现在**硬编码**（**应改用采到的 `Row.IsLight`**） | — |

- **S1** **单 key** 请求 ⇒ 客户端 `trim = list.Count >= 2` 为 false ⇒ 回**原始缓冲**（我们自己裁）
- **S2** **多 key** 请求 ⇒ `trim = true` ⇒ 客户端按**硬编码** `killTime − 3f` ~ `_killLocalTime + 5f` 自己裁，
  且**分基**（下界用基 S、上界用基 C）
  ⇒ 我们自造的 key（`BaseKey + 100/200`）量纲不符 ⇒ **裁出空带** ⇒ 静默降级
  ⇒ **所以必须每个 key 单独发一包**
- **S3** `BuildUploadTape` 有四段 `return value` 回退（无 MyPlayer / 无基准时刻 / 无自身 SpawnShot / 结果 < 2 帧），
  每一段都会**放弃裁剪、返回原表**

## 5. 三个角色（必须分开命名 —— 这是最大的错误来源）

| 角色 | 含义 | 约束 |
|---|---|---|
| **SubjectId** | 镜头要拍谁 | 服务端合成时相机只能跟着他；**原版没有"把相机送到别的房间"的实现** |
| **RecorderId** | 谁能提供磁带 | 只有真人；假人为 0 ⇒ 必须服务端合成 |
| **SilhouetteId** | 首帧给谁（= 剪影落点） | **不能是 SubjectId**（否则他被涂黑）；**不能用 0**（本机特殊值，各机解释不同、会互相冲突） |

现有实现用一个 `Clip.RecorderId` 同时承担这三个含义，是反复出错的根源。

## 6. 幕序与 key

- 客户端 `_playTapes` 是 `Dictionary<int, List<SnapShot>>`
  ⇒ **播放顺序 = key 顺序**，且**同 key 会覆盖**（后到者赢）
- 幕序（我们的口径）：**拿刀 → 杀人 → 最后时段 → 白方各段 / 自爆 → 黑方收尾**
- ⇒ key 必须**唯一且单调递增**。现有实现靠 `+1 / +100 / +200` 手工偏移 ⇒ 重写时应由**幕表下标**派生
- 反例（已踩）：`SurviveTime` 在结算时**已停走** ⇒ 所有请求拿到同一个 base ⇒ 必须自己加偏移区分

## 7. 结算编排

- 拦截点：`GameRoom.ChangeGameState(EGameState.TotalResult)` —— 三个调用点（`GameOver` 的推送 / `ClearAllMission` / `Trial.FinalizeTrialResult`）都走它
- 回放期间**服务端必须保持 `Survive`**：
  - `TrialTick`（`:171536`，`if (State == Trial)`）会跑 `Trial.Tick()` ⇒ **原版裁判状态机接管**并广播讨论/投票界面
  - `GameOver` 末尾是 `if (State == EGameState.Survive) PushAfter(7500, …TotalResult)`（`:171403`）
- 客户端进 `Trial` **只广播 `S_CHANGE_GAME_STATE`，不改服务端 State**
- 客户端的换状态是**异步**的（走加载过渡）⇒ 必须等回执（`WaitCompletePacket`）
- 必须发 `S_FADE_IN` 收掉加载页（否则要等 18 秒的 `CompleteWatchdog` 兜底）
- 推 `S_TRIAL_STATE{Replay}` **之前**必须把全部磁带发完 ——
  `StartReplay` 会把 `_playTapes` **快照**进 `_session`，之后再补就进不了这一轮
- `MasterMind` 是**跨局**的 `GameRoom` 字段 ⇒ 必须清，否则原版会向黑方弹「你的合作黑幕是 X」
- 白胜 / 黑胜的判定要显式记录（现有实现靠 `GameOverNoteHook` / `WhiteWinNoteHook` 两个"只做记录"的钩子）

## 9. 验收判据（重写后怎么知道对了）

- [ ] 每一幕的 `主视角=` **不是** `原版 #N`（除非确实没有可用替身）

- [ ] 排序前逆序处数 = 0 或很小
