# 物品伪装（`[ItemDisguise]`）—— 机制与约束

> 状态：**实验性，已实现并构建通过；未实机验证。**
> 代码：`Features/Disguise/ItemDisguiseFeature.cs`（Host，纯服务端）。
> 测试口径：`docs/测试清单.md` 第 11 节。

## 1. 目标行为

1. 白方**持有**物品并原地静止 N 秒（默认 3）⇒ 伪装成该物品。不是“捡起后”才开始计时。
2. 手持物保留；自己客户端显示正常状态、可以移动；其他人只看到一个假物品。
3. 假物品跟随玩家位置（纯服务端 remove/spawn 跳步）。
4. 黑方 / 其他玩家 / 自己按 E 假物品 ⇒ 现形；手持物不掉。
5. 默认移动**不**解除（`RevealOnMove=false`）；打开后位置变化即现形。
6. 伪装期间禁止捡别的物品、用物品、丢物品、用技能、操作设备。
7. 自己身上刷新 `ShadowPartnerVfx` 虚影，只有自己看得到。

## 2. 为什么必须做“客户端状态欺骗”

服务端 `Player.State = Hide` 后：

- `Player.StartState(Hide)` 会 `SkillComponent.LockSkill()`、从观察者列表移除并 `S_DESPAWN`；
- 客户端 `FixedUpdateSurvive` 对 `State.Hide` 直接 `SetRigidBodyVelocity(Vector2.zero)`；
- 服务端 `GameRoom.HandleMove` 对 `State.Hide` 直接 return。

⇒ **真 Hide 下客户端不会真实移动，C_MOVE 是原地包**（位置不变、`IsMove=false`）。
只靠服务端无法判断“玩家想移动”。

本功能因此采用：

```text
服务端：State = Hide            （目标判定、观察者 despawn）
本人客户端：S_MODIFY_PLAYER(Idle)（只发给本人，身体正常、客户端真实移动）
```

配套：

- `Player.ModifyPlayer` Prefix：伪装期间忽略本人客户端的状态切换，
  避免原版“当前 Hide 拒绝离开”把 `Hide` 回发给本人；
- `GameRoom.HandleMove` Prefix：伪装期间自行更新位置，并同步假物品；
- `Player.StartState(Hide)` 仍会锁技能/移除观察者，保证黑方刀/DT 选不中。

**这是状态不同步的 hack，不是原版支持的正常状态。**
断线重连、死亡、回合结束、伪装期间的操作都要单独兜住。

## 3. 假物品

- 只创建 `DeviceInfo`（`EDeviceType.ItemHolder`），`StateList[0] = 手持物 DataId`；
- 加入当前 `Area.Info.DeviceInfos`，广播 `S_SPAWN_DEVICE`；
- **不加入 `ItemManager.ItemHolders`**，否则原版 `AcquireItem` 会真的把物品拿走；
- E 请求由 `ItemManager.AcquireItem` Prefix 拦截：
  - 按 `RevealDistance` 检查距离；
  - 黑方 / 伪装者本人 / `AllowOthersReveal` 允许的人 → `Reveal`；
  - 返回 false，不执行原版拾取；
- 伪装者自己客户端是 Idle，所以 `ItemHolder.GetInteractMessage` 会给“拾取”提示，
  可以按 E 自己的假物品主动现形。

## 4. 假物品跟随：能力与限制

**`S_MODIFY_DEVICE` 不能移动客户端物品：**

- 客户端 `Handle_S_MODIFY_DEVICE` → `DeviceManager.Modify`，只刷新
  Bubble / Mission / StateList，不改 transform；
- `ItemHolder.RefreshState` 只换图标；
- `Managers.Map.ModifyDeviceInArea` 是空函数。

所以纯服务端只能：

```text
S_REMOVE_DEVICE(旧位置)
更新 DeviceInfo.Pos
S_SPAWN_DEVICE(新位置)
```

即“跳步跟随”，会闪烁；由 `FollowInterval`（默认 0.3s）与 `FollowDistance`
（默认 48px）节流。平滑跟随需要客户端补丁。

## 5. 手持物保留

关键顺序：

```text
StartDisguise:
  KeepItemOnHide = true
  State = Hide          // StartState(Hide) 检查 KeepItemOnHide，保留手持物
  S_MODIFY_PLAYER(Idle) // 只发给本人

Reveal:
  RemoveFake
  State = Idle          // 此时 KeepItemOnHide 仍为 true ⇒ EndState(Hide) 不掉物
  KeepItemOnHide = 原值
  Move(当前位置)        // 让观察者重新 S_SPAWN
```

**顺序不能反**：先恢复 `KeepItemOnHide=false` 再切 Idle 会把东西掉出来。

## 6. 自嗨虚影

`PulseGhost` 用：

```csharp
S_PLAY_EFFECT {
    Type = EEffectType.ShadowPartnetVfx,
    DeviceId = 自己,
    Pos = 自己位置
}
```

只发给自己的 Session，不进任何世界广播。

事实（旧反编译 ACS，未用新版 IL 逐行复核）：

- `SkillComponent.UseRuleBreaker` 里是 `SendVFX(Owner, ShadowPartnetVfx, targetId)`；
- `SendVFX` 只发给施放者本人 + 死者，不是世界广播；
- 客户端 `PlayShadowPartnerEffect` 把 `ShadowPartnerVfx` **挂到本地 MyPlayer 身上**，
  使用目标角色剪影，约 2 秒淡出；
- 因此它**不能**让黑方/其他人看到虚影；发给别人会挂在别人自己身上，不是凶手/伪装者位置；
- 持续半透明身体、世界可见幽灵需要客户端补丁；`IsGhost` 是真正的幽灵语义，
  会影响 AOI/胜负/回放，不是纯外观开关。

## 7. 传统模式的文本与箭头

### 文本

- `TraditionalModeFeature.KnifeNotice` 生成
  `传统模式：黑方在「房间」计数 N 秒。`
- 自行跑刀：`BroadcastFeature.PostfixInsertWeapon` 把它拼在
  `WeaponTaken` + 黑方身份之前的**同一条通告最开头**；
- 自动发刀 / 开局提示：`SendStartTips` 计算一次 `AutoStartNotice(room)`，
  然后：
  - 白方：`传统行 + 黑方身份? + WeaponTaken + StartBodyWhite`
  - 黑方：`传统行 + StartBodyBlack`
  - 自行跑刀时若黑方在 3.2s 前已拿刀，黑/白都带传统行；
  - 若黑方在 3.2s 后才拿刀，则稍后的拿刀通告带传统行。
- 这解决了两个问题：
  1. 另发一条 `Notice` 会被后一条气泡顶掉；
  2. 黑方开局提示原本没有传统行。

### 箭头

- `TraditionalModeFeature.StartCountdown` → `NotifyBlackArrow(room)`；
- 对每个存活、非黑/暗、有 Session 的玩家发
  `S_NOTIFY_ARROW { Type = CharacterArrow, Pos = 黑方位置 }`；
- 等待结束 `EnterSearch`、黑方死亡、回大厅/换局、`CleanupBuffs` 时
  `ClearBlackArrow` 按同一坐标发 `S_REMOVE_ARROW`；
- 黑方在 `TheWorld` 冻结期间位置不变，所以只发一次；
- 客户端 `UI_Arrow` 会围绕目标点旋转；`CharacterArrow` 是否红色由客户端 prefab 决定，
  若要固定红色需要换 `EArrowType` 或客户端补丁。

### 与传统（经典）模式冻结的兼容

- `TraditionalModeFeature.IsFrozenPhase` = 本局传统模式生效且已经进入第二段 `Search`；
- **已经完成的伪装（`st.HasFake`）在冻结期间保留**：
  - `FreezeWhites` 只给白方 `AddBuff(Stop)`；`Stop` 在客户端只做
    `_lockControlStack++`（ACS:14922-14924），不改 `Player.State`；
  - `CancelTeleport` 只有在 `Owner.State == Casting` 时才会改状态（ACS:177505-177517），
    伪装者 State 是 Hide，不受影响；
  - 所以假物品、`HoldItem`、服务端 `State=Hide` 都保留，黑方仍然可以 E 翻出。
- **冻结开始时已经在 `Arming` 的白方继续完成伪装**：
  - `TickHook` 不再因 `IsFrozenPhase` 清掉 Arming；
  - `StartDisguise` 也不因冻结拒绝完成；
  - 冻结只锁操作（Stop），不改变服务端 `State`，所以计时可以继续。
- **冻结开始后不再新开 `Arming`**：
  - `BeginArming` 在白方 + `IsFrozenPhase` 时直接 return；
  - 已经在 `ByPlayer` 里的状态不会走 BeginArming，因此不受影响。
- 黑方/暗方不受白方冻结影响；若开启 `AllowBlackDisguise`，黑方仍可在 `Search` 阶段伪装。
- 白方被 Stop 后无法自己按 E（控制被锁），但黑方/其他玩家仍可 E；这是冻结语义，不是伪装丢失。

## 8. 配置

| 键 | 默认 | 说明 |
|---|---|---|
| `Enabled` | false | 段开关；测试时在 `.cfg` 设为 true |
| `StandSeconds` | 3 | 持有物品静止 N 秒 |
| `RevealDistance` | 450 | E 翻出距离 |
| `FollowInterval` | 0.3 | 假物品跟随节流 |
| `FollowDistance` | 48 | 位移阈值 |
| `GhostInterval` | 1.8 | 自嗨虚影间隔 |
| `ReDisguiseCooldown` | 5 | 解除后重伪装冷却 |
| `AllowOthersReveal` | true | 非黑方其他人也能 E |
| `AllowBlackDisguise` | false | 不检查阵营，允许黑/暗伪装 |
| `RevealOnMove` | false | 移动后解除 |

## 9. 已知风险 / 未验证

- 客户端状态欺骗是 hack；断线重连可能把 Hide 快照发回，需要重新补 Idle。
- 伪装期间不能捡东西/用物品/丢物品/用技能/操作设备，已在服务端加门闩；
  其余交互路径（扫描、尸体、证据破坏等）尚未逐一补齐。
- 黑方伪装时 `Weapon` 与 `Hand` 是两套字段；当前只对 `Hand` 做条件，
  黑方是否能带刀进入伪装取决于它手里是否有 `Hand` 物品。
- 假物品跟随会闪烁；平滑跟随需要客户端补丁。
- 自嗨虚影在某些客户端缓存缺失时可能只留下空效果；未实机。
- 箭头颜色由客户端 prefab 决定；`CharacterArrow` 是否“红毛箭头”未实机确认。
