# HideAndSeek 知识索引（子会话动手前必读）

> 这一页解决一个具体问题：**已经查过的结论不要再查第二遍。**
> 动手前先读本页 + [事实索引.md](事实索引.md)。命中就直接引用；没命中再去 `../../.tmps/` 找该主题的原始调查；
> 两处都没有，才允许做全仓源码调查。
>
> **禁止**一上手就全仓 grep / 逐文件倒查源码 —— 本项目已积累 **44 份**调查报告，
> 绝大多数"系统倒查"都是在重复劳动。（复核你即将改动的那几行 ≠ 把整条链路重查一遍。）

## 0. 知识分层约定（本仓库的规矩）

| 层 | 位置 | 进 git | 放什么 | 寿命 |
|---|---|---|---|---|
| 过程材料 | `D:\git\DT_Tools\.tmps\`（**在本仓库之外**，相对本目录是 `../../.tmps/`） | ✗ 不进 | 原始日志、一次性脚本、草稿、调查报告的原始稿、被证伪的方案 | 可丢、可过期、允许被改写 |
| 耐久结论 | `HideAndSeek\docs\`（本目录） | ✓ 进 | 与实现无关的硬约束、会被反复引用的事实、规格、测试口径 | 长期，跟仓库一起 clone |
| 代码内规范 | `HideAndSeek\AGENTS.md`、`DEVELOPMENT.md`、`Features/UI/EXTENDING.md` | ✓ 进 | 编码铁律、踩坑清单、扩展方式 | 跟代码同步演进 |

三条操作规则：

1. **调查完成 ⇒ 必须回写 `docs/`。** 把结论（带**出处 + 置信度 + 未验证项**）提炼进 `docs/`；原始过程材料留在 `../../.tmps/`。
2. **`docs/` 里不许只留指针。** `.tmps/` 不在任何 clone 里、随时可能被删 ⇒ 结论必须自足，`../../.tmps/` 只当追溯线索。
3. **`docs/` 不放原始材料。** 大段日志粘贴、一次性脚本、还没验证的猜测留在 `../../.tmps/`。

> 与 `AGENTS.md`「设计备忘与调查」一节的关系：那一节说的是**过程材料别塞进 `docs/`**（仍然有效）；
> 本节补上另一半 —— **结论必须从过程材料里提炼出来、进 `docs/`**，否则下一个会话看不见，只能重查。
> 完整纪律见 `AGENTS.md` 的「知识复用纪律」一节。

## 1. 怎么读（给未来的会话 / 子会话）

```text
第 1 步  读本页（docs/README.md）+ docs/事实索引.md            ← 3 分钟，不许跳
第 2 步  命中 → 直接引用；只在"你要改的那几行"上用新版 IL 复核   ← 复核 ≠ 重查
第 3 步  未命中 → 在本页第 3 节按机制域找到主题，读 ../../.tmps/ 的原文
第 4 步  仍没有 → 才做全仓调查；做完按第 0 节规则回写 docs/
```

**状态口径**（第 3 节表格用）：

| 状态 | 含义 | 你该怎么做 |
|---|---|---|
| 已落地 | 结论已体现在代码里 | 直接引用；改它之前先读 `docs/` 里对应的机制文档 |
| 待决 | 方案/规格已定，或等房主确认，尚未实现 | 不要重新设计，先读它给定的模型 |
| 已证伪 | 该结论被推翻 | **不要照抄**；被推翻的原因也写在原文里 |
| 已被取代 | 有更新的文档覆盖它 | 读取代它的那一份 |
| 快照 | 内容随 `.cfg` / 代码漂移 | 只当参照，用前重新生成 |
| 待补 | 本索引只写到文件名级主题，摘要未核实 | 打开原文自己看，看完顺手补一行 |

**引用行号前先看 [事实索引.md](事实索引.md) 顶部的「口径与版本」** —— 行号属于哪一版反编译/程序集，决定它还能不能用。
